# System Architecture

## 1. High-Level Architecture
The system adopts a modern, decoupled client-server architecture enforcing a clean separation of concerns. The frontend communicates with the backend exclusively via REST APIs, ensuring the database is never directly accessed from the client.

```
[ Next.js Frontend ]  <--(REST API / JSON)-->  [ NestJS Backend ]
                                                     |
                                                (TypeORM)
                                                     |
                                                     v
                                           [ PostgreSQL Database ]
```

## 2. Component Details

### Frontend (Next.js)
- **Rendering**: Employs both Server-Side Rendering (SSR) and Client-Side Rendering (CSR) tailored to page requirements (e.g., SEO for course catalog, CSR for course player).
- **State & Data**: Manages server state and API data fetching using TanStack Query.
- **Forms**: Handles complex form states via React Hook Form and schema validation via Zod.
- **UI**: Styled with Tailwind CSS and utilizing shadcn/ui for accessible, reusable components.

### Backend (NestJS)
- **Structure**: Follows a strict modular architecture (e.g., AuthModule, UserModule, CourseModule) mapping cleanly to OOAD component diagrams.
- **Controllers**: Handle incoming HTTP requests and routing.
- **Services**: Encapsulate core business logic and orchestrate data flows.
- **DTOs**: Data Transfer Objects utilize `class-validator` to sanitize incoming payloads.
- **Documentation**: Autogenerated Swagger/OpenAPI specifications.

### Database (PostgreSQL)
- **Mapping**: Relational data model accessed through TypeORM entities and repositories.
- **Security**: Completely isolated within a private network tier; inaccessible from the public internet or frontend.

## 3. External Integrations
- **Payment Processing**: The NestJS backend integrates with the Stripe API to generate checkout sessions and exposes a secure webhook endpoint to receive payment confirmations.
- **Media Storage**: The backend uses an SDK (e.g., AWS S3 or Cloudinary) to upload static assets and media, storing only the resulting public URLs in PostgreSQL.
- **Email Service**: Integrates with an external provider (e.g., SendGrid/AWS SES) to dispatch transactional notifications.
